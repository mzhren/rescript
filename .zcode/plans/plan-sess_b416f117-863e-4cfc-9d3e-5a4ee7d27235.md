# 修复转写语言默认英语的 bug:加"自动检测"并设为默认

## Context(根因)

中文视频被识别成英语,是**两层默认强制英语**叠加的结果:
1. **transformers.js 4.2.0 根本没实现自动检测**——`node_modules/@huggingface/transformers/src/models/whisper/modeling_whisper.js:56-61`:`if (!language) { language = 'en' }`(旁边是 `// TODO: Implement language detection`)。不传 language = 强制英语。
2. **应用侧也默认英语**:worker 入口 `workers/transcription.worker.ts:1413` 的 `language ?? "en"`,且 `lib/languages.ts:14` `DEFAULT_TRANSCRIPT_LANGUAGE = "en"`,在 `transcription.worker.ts:1298` 一路传给 Whisper pipeline。

应用其实已有语言选择子菜单(`components/ModelSelector.tsx` 的 `LanguageSection`,持久化到 localStorage `rescript.transcript-language` 和项目文件),只是默认值错、入口不显眼。

**方案**:给 `TranscriptLanguage` 增加 `"auto"` 并设为默认;Whisper 路径在 worker 内用一步 forward 真正自动检测(取检测出的具体语言驱动解码和 CTC 对齐);选择器顶部加"自动检测"项,手动选择仍然可用(可覆盖误检测)。Parakeet 的 ASR 本身已自动检测语言,无需改动。

## 改动

### 1. `lib/languages.ts` — 增加 auto
- `TranscriptLanguage = "auto" | "en" | "es" | "fr" | "de" | "pt" | "zh"`
- `TRANSCRIPT_LANGUAGES` 加 `auto: { label: "Auto", nativeLabel: "Auto", flag: "🌐", code: "AUTO" }`(满足 Record 穷尽性;`code` 符合 `tests/languages-test.ts` 的 `id.toUpperCase()` 规则)
- `TRANSCRIPT_LANGUAGE_ORDER` 把 `"auto"` 放最前
- `isTranscriptLanguage` 接受 `"auto"`;`DEFAULT_TRANSCRIPT_LANGUAGE` 改为 `"auto"`(store/autosave/projects 的校验都走这个 guard,旧项目里已保存的 `"en"` 等选择保持不变)

### 2. `workers/transcription.worker.ts` — 真正的自动检测
- **入口 1413**:`const transcriptLanguage = language ?? "auto"`(类型随之含 auto)。
- **新增 `detectTranscriptLanguage(transcriber, audio, speechSegments)`**(放在 runWhisper 附近):
  - 取第一段语音段开头起 ≤30s 的音频(无语音段则取开头 30s / 整段音频);
  - `const features = await transcriber.processor(slice)` → `features.input_features`;
  - `transcriber.model.forward({ input_features, decoder_input_ids: new Tensor("int64", [decoder_start_token_id], [1,1]) })`——直接 forward 而非 generate,取 `out.logits` 在 `generation_config.lang_to_id` 的语言 token 下标范围内 argmax(排除时间戳/其它 token 干扰);
  - id → `"<|zh|>"` → `"zh"`,用 `isTranscriptLanguage` 校验;不认识的语言回退 `"en"`;整体 try/catch 回退 `"en"`。
- **`runWhisper` 调整顺序**:现在是对齐器预热发生在转写前且依赖语言;改为:先 `getAsr + getVad` → `detectSpeechSegments` → 若 `requested === "auto"`:post 一条 `progress.detectingLanguage` 进度后检测出具体语言 → 再做对齐器预热 → 之后 `asrOptions.language`、`refineWordTimestamps(...)` 全部用**解析后的具体语言**(这些下游代码零改动,`"auto"` 不会泄漏到它们)。
- **`runParakeet`**:`"auto"` 直接透传——`alignModelFor("auto")` 返回 null(`lib/alignModels.ts:50` 对未知字符串本来就返回 null)→ 跳过 CTC 对齐走 VAD 兜底;ASR 本身自动检测。

### 3. `components/ModelSelector.tsx` — UI
- 子菜单项循环里对 `id === "auto"` 特殊化:文案用 `t("model.languageAuto")`(其余仍用 `option.nativeLabel`),触发按钮同法;flag 用 `option.flag`(🌐)。
- 触发器徽标 `showLanguageInTrigger`(213-216 行)条件 `transcriptLanguage !== "en"` 对 `"auto"` 天然成立,无需改逻辑。

### 4. i18n — 新增 2 个 key,10 个语言文件
`lib/i18n/messages/{en,de,es,fr,it,ja,ko,pt,zh-CN,zh-TW}.ts`:
- `model.languageAuto`:"Auto detect" / "自动检测" 等(参考各文件现有 `model.language` 的译法风格)
- `progress.detectingLanguage`:"Detecting language…" / "正在检测语言…"
(`tests/i18n-test.ts` 强制 10 语言 key 对齐,漏一个会挂)

### 5. 类型与注释
- `lib/types.ts:103-105` WorkerRequest.language 的 doc 注释补一句 auto 语义(worker 内解析为具体语言)。
- `hooks/useTranscriber.ts` 的 telemetry 会把 `"auto"` 作为 language 上报,无需改代码,注明即可。

### 6. 测试更新
- `tests/languages-test.ts`:翻转 `isTranscriptLanguage("auto")` 断言(现在合法)、`DEFAULT_TRANSCRIPT_LANGUAGE === "auto"`、order/labels 期望串加 Auto 项。
- `tests/align-models-test.ts`:补 `alignModelFor("auto") === null` 显式断言。

## 验证

1. `npx tsc --noEmit`(tsconfig)+ `npx eslint` 相关文件
2. `npm run test:i18n`;`npx tsx tests/languages-test.ts`;`npx tsx tests/align-models-test.ts`
3. 手动(当前 electron:dev 仍在后台跑,Next 热更新后 Cmd+R 刷新应用窗口):
   - 载入中文视频 → 不选任何语言 → 转写结果应为中文,模型菜单触发器显示 🌐/自动检测
   - 手动把语言切到 English 再载入英语视频 → 仍正常(覆盖生效)
   - 切 Parakeet 模型 + auto → 转写正常(对齐走 VAD 兜底)
   - 首次检测会多下载对应语言的 CTC 对齐模型(仅当语言命中),UI 已有下载进度文案

## 已知限制(本次不做,可后续跟进)

- 检测只用开头 ≤30s 语音;片头音乐/多语言开头可能误判 → 手动选择即可覆盖。
- **预存在的库限制**(与本次改动无关):transformers.js 在 word-timestamp 模式下分词把语言 token 剥掉后再分词,中文文本因无空格会按"整段"成词,词级编辑粒度受影响。要修需再给 dist bundle 加 patch(patches/ 已有先例),建议另开任务。
- 语言选择改变不会自动重转写已有项目(现有设计,转写每视频一次)。
